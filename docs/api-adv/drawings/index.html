Drawings

This page describes the APIs Onshape provides for working with Onshape drawings.

ℹ️ Onshape API Notes

  • All Onshape API calls must be properly authenticated.
  • For Enterprise accounts, replace cad in URLs with your company domain.
  • Onshape IDs are written as: {did}, {wvmid}, {eid}, {pid}, {otherId}. See Onshape API Intro for information on what these IDs mean and how to obtain them from your documents.
  • The same ID is sometimes named differently in a response than in the request that uses it. For example, an element ID might be returned as id in one response and passed as {eid} or elementId in the next request. Check each endpoint's response and request schemas in the API Explorer to confirm which field to use.
  • Variables for replacement are written as: {variable1} or <variableTwo>. Never include the braces or angle brackets themselves with these variables.
  • Visit the Learning Center's Intro to the Onshape API course for additional instruction and videos.

Endpoints

To create drawings, Onshape allows you to send all drawing data points and information through the API as part of the request body JSON.

The following endpoints are available:

  • createDrawingAppElement: Create a drawing
    curl -X 'POST' \
  'https://cad.onshape.com/api/v6/drawings/d/{did}/w/{wid}/create' \
  -H 'Authorization: Basic CREDENTIALS' \
  -H 'Accept: application/json;charset=UTF-8; qs=0.09' \
  -H 'Content-Type: application/json;charset=UTF-8; qs=0.09' \
  -d '{
    <JSON request body options from the BTDrawingParams schema>
}'
    Specify the document in which to create the drawing in the URL, and pass any additional options as part of the request body. You can provide a name for the drawing, manipulate the drawing graphics area, specify a part or template to create the drawing from, and more.
    • See documentation for all available options in the API Explorer.
    • For instructions on viewing the documentation for the request body schemas, see our API Explorer page. Check out the Sample Workflows section below for some practical examples.



  • modifyDrawing: Modify a drawing and add annotations
    curl -X 'POST \
  'https://cad.onshape.com/api/v6/drawings/d/{did}/w/{wid}/e/{eid}/modify' \
  -H 'Authorization: Basic CREDENTIALS' \
  -H 'Accept: application/json;charset=UTF-8; qs=0.09' \
  -H 'Content-Type: application/json;charset=UTF-8; qs=0.09' \
  -d '{
      "description": "string",
      "jsonRequests": [ 
        {
          <JSON request body options from the jsonRequests schema>
        }
      ]
    }'
    Specify the drawing to modify in the URL, and pass the information on the modification in the request body.
    • Note that the jsonRequests schema is not defined in the Glassworks API Explorer; see the OnshapeDrawingJson repository for this information, and check out the Sample Workflows section below for some practical examples.
    • The description field is limited to 32 characters.
  • getModificationStatus: Get the status of a drawing modification
    curl -X 'GET' \
  'https://cad.onshape.com/api/v6/drawings/modify/status/{mrid}
  -H 'Authorization: Basic CREDENTIALS' \
  -H 'Accept: application/json;charset=UTF-8; qs=0.09' \
  -H 'Content-Type: application/json;charset=UTF-8; qs=0.09' \
    • Provide the modification ID (from the modifyDrawing response body) to get the status of the modification.
    • This call also returns the unique IDs of any annotations that were successfully created or edited.
    • The requestState field has three potential values:
      • ACTIVE: drawing modification is in progress
      • DONE: drawing modification finished successfully
      • FAILED: an error occurred and the drawing was not modified
    • To set up the call:
      • Replace {mrid} with the id returned in the modification response, and replace CREDENTIALS with your credentials.
      • Poll the modification status until the request is no longer ACTIVE.
      • POLL RESPONSIBLY. See Rate Limiting and API Limits for more information.
      curl -X 'GET \
  'https://cad.onshape.com/api/v6/drawings/modify/status/{mrid}' \
  -H 'Authorization: Basic CREDENTIALS' \
  -H 'Accept: application/json;charset=UTF-8; qs=0.09' \
  -H 'Content-Type: application/json;charset=UTF-8; qs=0.09' \
  • createDrawingTranslation: Export a drawing to JSON
    curl -X 'POST' \
  'https://cad.onshape.com/api/v6/drawings/d/{did}/w/{wid}/e/{eid}/translations' \
  -H 'accept: application/json;charset=UTF-8; qs=0.09' \
  -H 'Authorization: Basic CREDENTIALS' \
  -H 'Content-Type: application/json;charset=UTF-8; qs=0.09' \
  -d '{
      "formatName": "DRAWING_JSON"
      }'
  • getDrawingTranslatorFormats: View available drawing export formats
    curl -X 'GET' \
'https://cad.onshape.com/api/v6/drawings/d/{did}/w/{wid}/e/{eid}/translationformats' \
  -H 'accept: application/json;charset=UTF-8; qs=0.09' \
  -H 'Authorization: Basic CREDENTIALS'

Status codes

If a drawing modification call fails, the modifyDrawing response will return an error, as expected. However, if the call includes multiple modifications, it will return 200 if any of the batch modifications succeed. The status field for each modification includes the status of the individual operation. For example:

Examples - Create Drawings

Create a drawing

Endpoint

POST drawings/d/{did}/w/{wid}/create

Request Body

{
  "drawingName": "string",
  "elementId": "{sourceElementId}",
  "partId": "{partId}",
  "views": "one | four | suggested"
}

Notes

  • drawingName: Provide a name for the drawing element
  • elementId: Specify the elementId of the source Part Studio or assembly.
    • Be sure to use the target document information (the document to include the drawing in) in the path parameters and the source document information (the document that houses the part, Part Studio, or assembly to draw) in the request body.
    • externalDocumentId and externalDocumentVersionId (Optional): Provide the source document information to create a drawing from a Part Studio or assembly in another document.
  • partId: (Optional) Create a drawing of a specific part in a Part Studio. If not provided, the entire Part Studio is drawn.
  • views: Create one or four views, or allow Onshape to create suggested views.
    • If not specified, four views are created (Top, Right, Front, and Isometric).
    • If views = suggested, Onshape automatically picks the views to create based on MBD data, or creates four views if MBD data is not available.

Example

In this example, we’ll create a drawing from the FLYWHEEL part in this public document.

  1. Open an Onshape document in which to create your drawing.
  2. Start to form the createDrawingAppElement call. Replace {did} and {wid} in the URL below with the document ID and workspace ID of your document (i.e., the target document), and replace CREDENTIAL with your authorization credentials.
    curl -X 'POST' \
  'https://cad.onshape.com/api/v17/drawings/d/{did}/w/{wid}/create' \
  -H 'Authorization: Basic CREDENTIALS' \
  -H 'Accept: application/json;charset=UTF-8; qs=0.09' \
  -H 'Content-Type: application/json;charset=UTF-8; qs=0.09' \
  3. Add the request body information:
    • Add flywheelDrawing as the drawingName field.
    • We must specify the source document’s document and version IDs. Note that since our target document and source document are different, we use the external document and version ID fields.
    • We must also provide the ID of the part to create the drawing from, and the ID of the element (i.e., tab) in which the part lives.
      (Hint: You can call getPartsWMVE to get a list of part IDs in an element.)
      curl -X 'POST' \
  'https://cad.onshape.com/api/v17/drawings/d/{did}/w/{wid}/create' \
  -H 'Authorization: Basic CREDENTIALS' \
  -H 'Accept: application/json;charset=UTF-8; qs=0.09' \
  -H 'Content-Type: application/json;charset=UTF-8; qs=0.09' \
  -d '{
        "drawingName": "flywheelDrawing",
        "externalDocumentId": "e60c4803eaf2ac8be492c18e",
        "externalDocumentVersionId": "405ba186c3a70e0227ab2941", 
        "elementId": "6bed6b43463f6a46a37b4a22", 
        "partId": "JiD",
        "views": "four"
      }'
  4. Call the endpoint and open your document. Confirm that you see the new flywheelDrawing element containing the drawing:

Create and edit sheets

onshapeCreateSheets adds sheets, as Insert sheet does, or copies a sheet with its views (copyFrom), as Duplicate does. onshapeEditSheets changes what the Sheet Properties dialog changes: name, position in the sheet list, paper size, border and zones, scale, sheet format and sheet reference. Each request carries a sheets array and gets one result per sheet; a sheet that fails is left unchanged and the next ones are still processed. The export now also reports format, width, height, includeBorder and zones for every sheet.

Endpoint

POST /drawings/d/did/w/wid/e/eid/modify

Properties

PropertyDescription
sheetDetails- sheetDetails.logicalId: Required for editing.
- sheetDetails.name: Optional.
- sheetDetails.index: Optional. 1 = first sheet.
copyFromOptional. The sheet to copy, specified bylogicalId, name, or index.
sizeOptional.
- ANSI: A | A Portrait | B | C | D
- ISO and JIS: A4 | A4 Portrait | A3 | A2 | A1 | A0
- Custom
width, heightOptional. Available with size: "Custom" only.
includeBorderOptional. true to add a border.
zonesOptional. An object: horizontal and vertical (the number of zones), and startZone (BottomRight or TopLeft).
scaleOptional
formatReferenceOptional. A drawing template element. null on edit removes the format.
referenceDetailsOptional. Part or assembly already referenced in the drawing.

Notes

  • Export the drawing to JSON to get the IDs and coordinates needed for the call.
  • On a sheet with a formatReference, the size, width, height, includeBorder and zones fields come from the format and are refused, unless the same request removes the format.
  • Only the paper sizes listed in the Sheet Properties dialog for the drawing standard are accepted.
  • The last sheet created becomes the active sheet.

Request Body - Create

Creates a B-size sheet at scale 1:2.

{
  "description": "string",
  "jsonRequests": [
    {
      "messageName": "onshapeCreateSheets",
      "formatVersion": "2021-01-01",
      "sheets": [
        {
          "sheetDetails": {
            "name": "Sheet A",
            "logicalId": <logicalId>
          },
          "size": "B",
          "scale": {
            "scaleSource": "Custom",
            "numerator": 1,
            "denumerator": 2
          }
        }
      ]
    }
  ]
}

Add and edit a hatch

Add a hatch on a drawing sheet or inside a view. Specify the region to hatch with an interior seedPoint, by the sketch entities that bound it (boundaryEntities), or both.

Endpoint

POST /drawings/d/did/w/wid/e/eid/modify

Properties

  • One of seedPoint and boundaryEntities is required:
    • seedPoint
      • Hatches inside a view must use a seedPoint.
      • If inside a view, provide the viewId and the view’s model coordinate array.
      • If on the sheet, provide the sheet’s coordinate array.
    • boundaryEntities
      • Specify the logicalId of each entity.
      • Accepts sketch entities on the sheet, not view edges.
  • Style properties are optional and match the Hatch region dialog:
    • pattern: Solid, ANSI, ISO and General patterns. See the Hatch region dialog for supported patterns.
    • scale: Defaults to 1.
    • angle: Defaults to 0 degrees.
    • lineWeight: The line weight of the pattern lines, in hundredths of a millimeter (50 is 0.50 mm). One of 13, 15, 18, 20, 25, 30, 35, 40, 50, 53, 60, 70, 80, 90, 100, 120, 140, 158, 200.
    • Use isPatternOverridden, isColorOverridden, and isLineWeightOverridden to follow (false) or override (true) drawing-wide settings. A pattern that differs from the drawing-wide pattern always overrides it, whatever isPatternOverridden says; the flag only matters when the pattern is omitted or equals the drawing’s.
  • viewId, patternCategory: Read-only, available on export.

Notes

  • Use messageName: onshapeEditAnnotations and the hatch’s logicalId to edit a hatch region.
  • The hatch’s boundary cannot be edited; to change the region, delete the hatch and create it again.
  • Only one region per hatch is allowed: a boundary that encloses several regions without a seed point (or a seed point in an already hatched region) are rejected.
  • A pattern too dense for its scale is rejected on both create and edit.
  • A Solid fill has no pattern lines, so lineWeight is refused on it and is not exported for it.
  • When an exported hatch says isLineWeightOverridden: false, set the flag to true (or remove it) along with a new lineWeight; with the flag still false the new value is ignored. The same applies to isColorOverridden. A new pattern needs no flag change: sending a pattern that differs from the drawing’s overrides it even with isPatternOverridden: false.
  • To go back to the drawing’s line weight, send isLineWeightOverridden: false alone.
  • Export the drawing to JSON to get the logical IDs and coordinates needed.
  • Delete the hatch with onshapeDeleteEntities.

Move a bend note

An Onshape::BendNote is the note Onshape places on each bend line of a sheet-metal flat pattern view, such as "UP 90.0° R.200". Bend notes are created with the view, so the API exports them and edits their two grips: position (text center, sheet coordinates) and attachmentPoint (on the bend line, view model coordinates).

Endpoint

POST /drawings/d/did/w/wid/e/eid/modify

Notes

  • Export a Drawing to JSON to get the logicalId of the bend note to edit.
  • A create request for Onshape::BendNote is rejected.
  • Bend notes cannot be deleted.
    • In an onshapeDeleteEntities request, a bend note fails with Cannot delete bend note; the other entities in the request are still deleted.
    • To hide bend notes, turn them off on the view.
  • Read-only properties are returned during export but ignored if sent on edit:
    • bendLineText
    • direction
    • angle
    • radius
  • The attachment point must be on the note’s own bend line; a note cannot move to another bend line.
  • Bend notes of a view with showBendNotes: false are not exported.

Show the center of mass in a view

The center of mass is not an annotation type but a property of the view, sent with onshapeCreateViews / onshapeEditViews and exported on every view. showCenterOfMass shows or hides the center of mass symbol, as Show / Hide center of mass in the view’s context menu does. The view exports its id in centerOfMassLogicalId, also while it is hidden; a point-to-point or point-to-line dimension, or a callout leader, attaches to the center of mass by using that id as the point’s logicalId, with snapPointType: "ModeCenter". The parts need a material, as in the UI.

You can Export a Drawing to JSON to get the IDs and coordinates used below.

Endpoint

POST /drawings/d/did/w/wid/e/eid/modify

Properties

PropertyDescription
showCenterOfMassOptional. Default is false.
centerOfMassLogicalIdOptional. Exported on a view that has a center of mass. Sent, it needs showCenterOfMass (true or false) in the same request; a name (not an h: logical ID) is kept so later requests can reference the center of mass by it.

Notes

  • Hiding is not deleting: dimensions on the center of mass stay, and showing it again brings back the same symbol. onshapeDeleteEntities on it is refused.
  • The request is refused where the context menu would not offer the center of mass, for example parts without a material, exploded views, or flattened sheet metal.
  • A point on the center of mass is exported in sheet coordinates without a viewId.
  • A re-created view gets a new center of mass id; to reattach dimensions, send a name in centerOfMassLogicalId and use it in the later request.

Add a threaded dimension

There is no specific threaded dimension type. A point-to-point, point-to-line, or line-to-line dimension placed on the thread edges of a hole or thread, and sent with isThreadedDimension: true, becomes a threaded dimension. The text shows the thread callout (for example M5x.80) or the thread depth, and the export marks it with isThreadedDimension: true.

Endpoint

POST /drawings/d/did/w/wid/e/eid/modify

Notes

  • Export the Drawing to JSON to obtain the IDs and coordinates needed.
  • isThreadedDimension - Required (true) to create a threaded dimension. Without it, or with false, a plain dimension is created, even on thread edges.

  • textOverride is exported only on a threaded dimension to hold the thread callout or depth. A value sent on create or edit is ignored, with no error. prefix, suffix, textAbove, and textBelow still apply.
  • The exported coordinates can differ from the ones sent; the dimension snaps to the thread geometry, as in the Onshape UI.

Add a minimum or maximum dimension

A min/max dimension measures the smallest or largest distance between two circles or arcs, such as two holes. It is a point-to-point or point-to-line dimension whose circle points carry anchorType: min for the nearest point of the circle, and anchorType: max for the farthest.

Endpoint

POST /drawings/d/did/w/wid/e/eid/modify

Properties

  • Export the Drawing to JSON to obtain the IDs and coordinates needed.

Show a dual dimension

A dimension can show a second value in the dual unit, as the Dual dimension switch of the dimension palette does. isDualDimensionEnabled turns the second value on or off; unit.dualUnit only chooses its unit. The dual value and the dual tolerance have their own precisions, unit.dualPrecision and tolerance.dualPrecision. Each value has an override flag: false makes it follow the drawing again. This works on point-to-point, point-to-line, line-to-line, radial, diametric, ordinate and arc length dimensions; a chamfer dimension takes the switch and a dual precision per value, and a hole callout takes the switch only.

You can Export a Drawing to JSON to get the IDs and coordinates used below.

PropertyDescription
isDualDimensionEnabledOptional. The Dual dimension switch.
isDualDimensionOverriddenOptional. false: follow the drawing; isDualDimensionEnabled is then ignored.
unit.dualPrecisionOptional. Decimal places of the dual value, 0 to 8.
unit.isDualPrecisionOverriddenOptional. false: follow the drawing’s dual precision.
tolerance.dualPrecision
tolerance.isDualPrecisionOverridden		Optional. Dual tolerance precision, 0 to 8, for every tolerance type except None. On a chamfer: toleranceFirstValue / toleranceSecondValue.

PropertyDescription

fontOptional. A font name as exported, for example NotoSans or Arimo.

Add and edit a revision table

A revision table (Onshape::Table::RevisionTable, body key revisionTable) lists the drawing’s revisions; its rows come from the revision history, as with the Insert revision table tool. A drawing has one revision table, shown on every sheet: a create adds it to each sheet, and the table settings apply to all of them. Position, sizes and cell formatting apply to the table of one sheet. The cell text is read-only.

A custom table (Onshape::Table::CustomTable, body key customTable) is the table the Custom table tool inserts: its rows come from a FeatureScript table function in a Feature Studio, evaluated on a Part Studio.
